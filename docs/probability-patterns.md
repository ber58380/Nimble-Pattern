# 概率样板

在 JEI 中将受支持的概率配方通过加号填入 AE2 样板编码终端后，服务端会根据配方 ID 读取真实配方，并把显示的产出数量改为期望数量。数量使用分数计算；有小数时，所有输入和输出统一按分母最小公倍数放大。

例如 `1A → 50% × 2B` 显示为 `1A → 1B`；`1A → 10% × 1B` 显示为 `10A → 1B`。只折算 JEI 实际填入的产物，不主动增加被 JEI 隐藏的副产物。概率消耗的输入仍按完整数量投料。

第一次编码写入“概率样板”标记。输出槽中仍放着该概率样板时，不改变配方再次编码得到普通 AE2 样板，**保留当前数量**。从 JEI 导入后，可以删去由玩家自行供应的输入（例如龙纳米蜂群），也可以自行修改产出数量；只要输出仍属于导入配方且包含概率产物，就保留概率标记，编码不会再次覆盖玩家填写的数量。导入另一配方会重新识别，换成无关产物或只保留必定获得的产物不会沿用旧概率标记。

机器执行次数根据保留的输入数量计算，与手动调整的产出数量无关；如果修改后的输入无法确定执行次数，则使用超时判定。

## 当前识别范围

- GTCEu/GTL：独立滚动（OR，包括 GTL LongChanceLogic.OR）的物品和流体输出；使用原始配方的 `chance / maxChance`，不固定假定分母为 10000。即使配方带有 `tierChanceBoost`，也只采用基础概率，不应用电压、超频或 JEI 显示等级的加成。
- Create：普通加工配方的滚动产出；序列装配按最终产物池权重计算，不把每次装配循环误当成一次成功率判定。
- AND/XOR 等规则、每 tick 输出或无法准确解析的第三方配方，保持普通样板，不猜测其概率。
- 手工填入处理样板没有配方 ID，不扫描整个配方库猜配方；需要从 JEI 导入以启用自动识别。

## 执行与补料

- 标准 AE2 供应器记录真正选中的投料方向。GTCEu 机器，以及能唯一解析到控制器的输入仓、样板总成，通过 RecipeLogic 完成事件计数；不会因为缺电或暂停判为失败。
- 已有工作无法归属、共享多个控制器的仓室、复杂子网、Create 处理链或不支持的机器状态接口，使用等待超时。默认 120 秒，配置为 `config/nimble_pattern-common.toml` 的 `probabilityPatternTimeoutSeconds`，范围 1～86400（按游戏 tick 计时）。
- 已知机器等待全部投料对应的配方完成后，留出 20 tick 的回流时间，再检查剩余产物。未知机器使用上述超时。
- CPU 从存档重载后，不能可靠恢复已经发生的机器完成事件与任务的对应关系；这部分在途投料重新使用超时判定，不会因等不到旧事件永久卡住。
- 失败时异步计算缺失数量的补单，把材料计划追加到原 CPU。已经到货的材料保留，替代投料不会重复增加欠交产物数量。
- 缺料时广播“概率合成失败 / xx概率合成缺失材料”，任务等待补料。相关 CPU 优先于普通 CPU 接收它正在等待的材料和产物，只接收所需数量。
- 取消会停止后续补单；CPU 中的真实物品交给 AE2 正常返还。已经交给机器的投料无法撤回。

## 验证范围

自动测试覆盖数量折算、元数据、共享机器完成事件分配、补单状态保存、取消，以及实际 AE CPU 的一次失败—缺料—补料—成功流程；存储服务和供应器使用测试替身。GTL 整合包与 Create 的实际机器投料、JEI 客户端交互仍需游戏内验证。本项目不会向整合包自动复制 jar。
