# Nimble Pattern 开发者审核文档

## 1. 阅读范围与证据口径

本套文档面向源码审核，不是玩家教程，也不是已通过安全审计的声明。整理日期：2026-10-03。审核对象是整理时的**整个工作区状态**，而非只有最近一次图标修改。

Git 比较基准：`df96c5cbb2e8752cf57fad1676a40d507aece4cd`。工作区有大量未提交修改和未跟踪文件，因此：

- “修改”表示相对上述 HEAD 的差异，不表示全部由最后一次任务产生。
- “新增/未跟踪”表示当前文件未进入 Git 索引；它可能已在多轮开发中存在，不能据此推断创建时间。
- “无差异”表示 HEAD 已有该实现；仍列出它的职责，便于审核整个功能。
- 已删除类也纳入清单。历史重命名按当前实现解释，不伪造 Git 没有记录的逐轮变更历史。
- 本次只新增审核文档，不修复在审阅中发现的代码风险，也不向 GTL 整合包部署 jar。

文中的方法名、NBT 键、注入点和限制以当前源码为准；历史需求与当前实现不一致时，明确写出差异。文件清单附内容 SHA-256，供其他开发者确认自己审核的是同一份源码。

## 3. 基础环境

当前构建配置：Minecraft 1.20.1、Forge 47.4.16、Java 17、AE2 15.4.10、GuideME 20.1.14；版本号 `1.20.1-1.0.3`。这些是本工作区配置，不表示任意更高版本都兼容。

AE2 是硬依赖。ExtendedAE、JECharacters、GTCEu、GTLCore、GTLAdditions 为可选兼容目标；开发运行依赖不等同于最终 jar 内嵌依赖。概率适配中的 Create 采用反射，没有开发环境实机验收保证。详见构建和 Mixin 章节。

## 4. 全局结构

```text
实体编码样板 + nimble_pattern 注解
    → 供应器 getAvailablePatterns / ProviderState 编译
    → NimbleEncodedPattern / NimbleAssemblerPattern
    → AE 合成计划（循环折叠、工具一次预留）
    → CPU 分派（普通 AE / 工具 / 循环 / 概率记录）
    → 真实供应器与机器
    → CPU 收货：工具 → 循环 → 概率补料 → AE 等待账本/模糊匹配
    → 请求者交付、余量回网、释放预留状态
```

管理平面独立于执行平面：终端更新条件与来源位置不应改变正在执行的样板身份；概率/循环/工具和模糊执行标记会改变执行语义。

## 5. 必须维持的不变量

1. 真实物品和“等待产物数量”是两套账，不能以扣减等待数代替真实物品交付。
2. `SIMULATE` 不修改存储、工具/循环控制器或模糊账本。
3. 普通配方仍由 AE 执行；特殊控制器只有符合对应条件时才介入。
4. 工具和循环种子不能凭空生成；失败、拒绝投料、取消都要保持物料守恒。
5. 概率补单可以增加待执行步骤，但不能为替代同一笔欠产出再增加一份最终欠账。
6. 发给供应器的身份必须是该供应器认识的原始样板；不能依赖包装类与原类不对称的 equals。
7. 第三方状态或配方语义不明确时，应拒绝恢复/解析或走明确的退化路径。
8. 客户端槽位只是显示；真实库存修改在服务端。现有安全边界是否足够，须按风险清单进一步审核。

建议先阅读 01、07、08，再按具体功能进入其他章节，最后依据 09 核对所有文件。
