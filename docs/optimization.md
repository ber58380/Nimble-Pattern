# 样板执行与性能优化

## 数据与兼容性

- `LoopStorageTier` 驱动五种元件注册，共用 `LoopStorageCellItem`。复用 AE2 `StorageTier` 的容量和待机耗电；物品注册名、材质路径、配置及内容 NBT 不变。
- `PatternMetadata` 为不可变的解码结果。包装样板的哈希和相等性不再临时构造 ItemStack / 复制 NBT。
- 执行身份区分模糊模式，不包含更新状态、更新条件、来源槽位等管理注解。原始样板与包装样板不跨类型相等。
- `ProviderPatternIndex` 显式映射执行身份到供应器原始样板，避免重载后的执行标记破坏供应器查找。供应器重建会替换映射。
- 供应器卸载时主动移除映射，并用注册实例校验防止旧状态误删新缓存；GTL 查询批处理上限时同样使用原始样板身份。
- 模糊模式和等待索引写入 CPU 存档。更新前已经运行的旧模糊任务没有保存这些信息，无法无损推断；升级前建议先完成或取消这些旧任务。

## 高频路径

- 概率元数据恢复按供应器建立一次候选索引，按主产物分组；普通重复配方仍会阻止有歧义的恢复。不存在概率样板时不解码整柜处理样板。
- 原版供应器缓存编译后的样板列表，原始样板对象或模糊卡状态改变时重建。
- CPU 收货入口明确按工具、循环中间物、概率补料顺序分流；物品库存与完成欠账保持分离。
- 工具、循环和概率控制器按需创建。普通任务不分配工具结果列表，不创建概率控制器；普通 GT 配方结束且无追踪票据时不运行反射解析。
- 模糊收货只按 AE 等待库存的实际扣减记账，精确收货同步移除模糊索引，模拟不修改账本。
- 概率收货按产物索引定位批次，同一次检查中复用机器查询、活动产物集合及待产出查询结果；同产物失败批次合并补单，保留各自欠账归属。
- 机器访问方法按类型缓存，完成或取消时主动注销票据。没有活跃概率任务时，网络走 AE 原路径；有活跃任务时优先遍历活跃 CPU 与当前网络的交集。

## GTL 批处理

概率样板不再固定限制为一次操作。GTL `getOperations` 的批次值传递到 CPU，预期产物和机器执行次数各自按批次放大一次，并在派发前限制乘法溢出。工具样板仍限制一次操作：同一份真实工具不能同时被多个合成借用。工具继续留在 CPU 内复用。

只读检查了本机 GTLCore 的批处理字节码。自动测试使用开发环境 AE/GT 及受控供应器，不等价于完整 GTL 总成、机器和复杂子网实机验收；没有向整合包复制构建产物。

## 样板更新与终端

- 更新条件由服务器追踪所有活动网络，不再由最后打开的终端覆盖。保留原本“条件获得后全服匹配样板更新”的语义。
- 第三方库存采用每 20 tick 的兼容轮询。只为改变了版本的库存重建条件索引，只复制实际需要修改的样板。条件提醒最多增加约一秒延迟。
- 打开的终端每 5 tick 检查网络变化，共享库存快照，只有版本变化时才生成槽位差异；条件没变化时不重新排序条件列表。
- 客户端合并一帧内的增量刷新，仅在滚动、布局或数据改变时重建可见槽位。
- 服务器停止时清理跨存档索引和机器票据。

## 验证

执行 `gradlew.bat build runGameTestServer`。新增测试包括模糊收货及持久化、身份对称性、执行模式区分、供应器原始身份恢复、元件注册参数及累加标记、候选歧义、批次产出记账、完成票据释放、跨网络无终端更新、共享快照扫描次数与多批次缺额合并。

扫描次数测试验证 512 次样板查找只读取实体库存一遍，以及同一检查周期 20 个快照读者不会重复扫描。它是复杂度回归验证，不是 GTL TPS 或耗时提升百分比。实际收益仍应通过大样板库、多 CPU 并发及多人终端的整合包负载测试确认。
